# Evergrove

A cozy, deep farming and life game for Roblox. Grow a farm from a small plot into a sprawling estate: till, water and fertilize living soil, chase weather-driven mutations, breed better seeds and hybrid species, raise animals with personalities and genes, run artisan machines and automation, befriend a village of 18 villagers, explore 16 regions, fish, mine, forage and dig, take part in festivals, and farm together with friends.

Everything in this folder is a complete Roblox Studio project, synced with [Rojo](https://rojo.space). The world (village, farm lots, regions, caves and sky islands) is generated by code when the server starts — there are no place files to import.

See **[docs/DESIGN.md](docs/DESIGN.md)** for the architecture and how every system works.

## Installing

You need Roblox Studio and Rojo 7.

1. Install [Rokit](https://github.com/rojo-rbx/rokit) and run `rokit install` in the **repository root** (it installs Rojo, StyLua and Selene from `rokit.toml`).
2. Install the Rojo plugin in Studio (`rojo plugin install`, or Plugins → Manage Plugins).
3. In Studio, create a new place from the **Baseplate** template and save it.
4. In a terminal: `cd evergrove` then `rojo serve`.
5. In Studio, open the Rojo plugin and click **Connect**. The code syncs into ReplicatedStorage, ServerScriptService and StarterPlayerScripts, and the project file sets up Lighting (Future), streaming and a few StarterPlayer properties.
6. Press **Play**. The server builds the valley on start (the template baseplate is removed) — give it a few seconds the first time.

To produce a place file without Studio sync: `cd evergrove && rojo build -o evergrove.rbxl`.

### Game settings

Set these in **Game Settings** (File → Game Settings) after publishing:

- **Security → Enable Studio Access to API Services**: needed for saving in Studio (DataStores and MemoryStores). Without it everything runs, but progress lives in memory and resets each session.
- **Places → Max Players: 6**. The world has 6 farm lots and every player gets their own; a 7th player would have no farm.
- **Avatar**: R6 and R15 both work (tool holding, emotes and action animations adapt to either rig).
- Optional: in the Terrain editor enable **Decoration** for animated grass (scripts can't turn it on).

### Configuring monetization, badges and admins

- **Store** — `src/shared/Config/Store.luau`. Create game passes / developer products in the Creator Dashboard and put their ids in `GamePassId` / `ProductId`. Items with id `0` show as "Coming soon". The store only sells cosmetics and conveniences: no crops, coins, speed or luck.
- **Badges** — set `BadgeId` on achievements in `src/shared/Config/Achievements.luau` (0 = no Roblox badge).
- **Admins** — `src/shared/Config/Gameplay.luau` → `Debug.Admins` (user ids) and/or `Debug.Group = { GroupId = n, MinRank = n }`. In Studio everyone is an admin, and so is the owner of a user-owned place. Open the admin console with **F8** (configurable) and type `help`.
- **Audio** — `src/shared/Config/Audio.luau` names every sound. They default to Roblox's built-in sounds so the game is never silent; replace any `Id` with an asset from the Creator Store. The soundtrack is generated live and follows seasons, weather, time of day and regions.

## Tests and checks

The shared code (every config module, the item registry and all game math) runs outside Studio under the standalone [Luau CLI](https://github.com/luau-lang/luau/releases). The harness bundles `src/shared` with a tiny fake Roblox runtime and runs `tests/spec.luau`, which validates every cross-reference between content modules (items, recipes, machines, shops, quests, NPC gifts, regions, festivals, achievements…) and unit-tests the crop, market, genetics, quality and contest math:

```
python3 tests/bundle.py --luau /path/to/luau
```

Type checking and lint (optional, recommended before commits):

```
rojo sourcemap default.project.json -o sourcemap.json
luau-lsp analyze --definitions=globalTypes.d.luau --sourcemap=sourcemap.json --ignore "**/tests/**" src
stylua --check src
selene src
```

(`globalTypes.d.luau` comes from the [luau-lsp](https://github.com/JohnnyMorganz/luau-lsp) releases; Selene downloads the Roblox API dump on its first run.)

## Adding content

Almost everything is data. Add an entry to the matching config module and the rest of the game picks it up — the registry generates items, the collection book gets an entry, shops/recipes/quests can reference it, and the tests check every reference.

- **Crop** → `Config/Crops.luau` (seed + produce items, artisan products for its tags, collection entry and a 3D model from its `Visual` archetype are generated).
- **Mutation / combo** → `Config/Mutations.luau` (conditions, multiplier, visual).
- **Weather** → `Config/Weather.luau` (visuals, crop effects, market demand, fish, hazards).
- **Machine** → `Config/Machines.luau` plus a placeable in `Config/Placeables.luau` with `Function = { Kind = "Machine", Machine = id }`.
- **Recipe** → `Config/Recipes.luau`. **Item** → `Config/Items.luau`.
- **Animal** → `Config/Animals.luau` (coats, patterns, product, model shape).
- **NPC** → `Config/NPCs.luau` (look, schedule, gifts, lines, events, perks) and optionally a shop in `Config/Shops.luau`.
- **Quest** → `Config/Quests.luau` (objectives, requirements, rewards, dialogue).
- **Region** → `Config/Regions.luau` (bounds, unlock, weather twists, hazards, nodes, forage, bugs, fish waters, dig loot); its terrain goes in `World/RegionBuilder.luau`.
- **Festival** → `Config/Festivals.luau` (activities, challenges, shop, prizes).
- **Placeable / decoration** → `Config/Placeables.luau`; new shapes register a builder in `Models/`.
- **Achievement** → `Config/Achievements.luau` (stat goal or special grant).
- **UI screen** → a module in `src/client/UI/Screens/` returning `{ Id, Title, Icon, Size, Watch?, Build }`; open it with `C.Windows.Open(Id, args)`.
- **Server feature** → a service module in `src/server/Services/` added to `init.luau`; declare its client actions (rate limit + argument schema) in `Lib/Net.luau`.
